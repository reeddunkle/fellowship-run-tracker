11 · Boilerplate factories (small, mechanical)

Worth exploring in-process
  • HTTP errors: "log, then fail with InternalServerError" appears 12× across 9 groups (4 variants in fellowship-logs-api-layer.ts). Replace with one internalServerError(message).
  • Catalog groups: the abilities, units and dungeons API layers and their 4 catalog mocks are identical except for names. Replace with one factory each.
  • DAO errors and decoding: 8 copies of mapXDAOError (configuration's is duplicated in the same folder) and about 15 decodeXRows. Replace with generic decodeRows(Model) plus a wrapUnexpected static.
  • Database wiring: the CLI setup-database command repeats the 4-database mergeAll, and Layer.unwrap(getDatabaseOptions…) appears 4×. Export makeDatabasesLayer from db.
  • FileMonitor pass-throughs: findLatestFile only forwards, readLines/readEvents are used only by tests, and the FileData construction is copied into the test harness.
  • Wire schemas: *-api-schema files are split between shared and api-contract, and some shared files are used only by Electron.

Quick wins

  • Dead code: FellowshipLogsGateway.streamEvents (live + fixture) has no callers. DAO.getByDungeonRunId is unused outside its DAO.
  • tools/dev-scripts/src/get-event-type-set.js is referenced nowhere, and its usage message names the wrong file.
  • The root format:sql script has no target. format:db-sql is a pass-through alias.
  • Root tsconfig.json references leave out packages/db, packages/json-schemas and apps/cli.
  • Two identical 116-line configuration.ts test fixtures (livesplit and websocket basic-test).
  • In file-monitor-test-harness.ts, the export FileMonitorTestDependenciesLive shadows a local with the same name and a different meaning.
  • The "already imported" check is duplicated in FellowshipLogs and the importer. Keep the importer's.
  • classify-tracking-failure.ts uses Match for a single case.
  • The "detachedWindow=true" string is duplicated between renderer and main. Move it to shared.
  • Context convention is mixed (.Provider vs React 19 <Ctx value>). Some imports lack the .ts extension (the *-client.ts files, main.tsx).
  • 6× redundant errors.length > 0 guards around FieldError, which already returns null.
  • Nothing checks that the generated milestone JSON schema or the catalog checksums are up to date. Consider "regenerate, then git diff --exit-code" in check.
  • The domain status schema lives in api-contract, which forces packages/db to depend on api-contract. Move it to shared.

Looked at and fine as is: Biome, oxlint and Prettier each have a distinct job. The configuration DAO and the background-job DAO are already deep.

Top recommendation

1 · One live log stream carries status and events

It removes three translation layers, fixes the known Tracking status bug in docs/tasks.md, drops the 250 ms e2e workaround, and makes it impossible for status and events to disagree. Next, take #2: it unblocks the observation-batching task.
